Hard walls we smashed through

  1. PROBLEM 01100-year-old crooked courthouse scans & runaway vision API bills

    HOW WE FIGURED IT OUTBuilt local zero-cost OCR inside Electron's main process (tesseract.js + @napi-rs/canvas) plus automatic second-reads when tract legal descriptions spill onto attached exhibits.

  2. PROBLEM 02CourthouseDirect & TexasFile session locks and missing clerk index rows

    HOW WE FIGURED IT OUTEngineered persistent browser profiles and a stated-source-deed fallback lookup that pulls instruments directly when a county clerk's index omits a recited book and page.

  3. PROBLEM 03Hallucinated mineral fractions, sheriff deeds & namesake decedents

    HOW WE FIGURED IT OUTWrote a typed chain-of-title derivation engine where a sheriff or the State is never mistaken for a surname, initialed decedents never corrupt estates, and two independent examiners + a validator must reconcile 212.5400 net mineral acres before export.

  4. PROBLEM 04Stalled runs at 16%, provider rate-limit storms & silent worker deaths

    HOW WE FIGURED IT OUTWired five-account model failover across Gemini, Ollama Cloud, Claude, and Codex, persistent replay checkpoints, and built our own 65-commit Karpathy Loop Harness to seed regressions and prove autonomous repair.

  5. PROBLEM 05Google OAuth & CASA verification walls blocking landmen

    HOW WE FIGURED IT OUTBypassed brittle OAuth prompts on desktop with direct Drive-for-desktop mount detection and company-vs-personal boundaries, then split web intake from dedicated worker servers to take title-desk.com and artificiallandman.io live online.

Twelve ways agent systems fail — and the control that fixes each.

Most broken automation doesn’t fail because the model is bad. It fails because the operating layer around the model is missing. Select the symptoms you recognise and they are added to your brief.

  1. No acknowledgement, retry queue, or dead-letter path, so customer work quietly disappears.

  2. Agents loop, retry too fast, or use expensive models for cheap work.

  3. Shared keys, no backoff, and too many workers make providers reject useful work.

  4. The health check says the app is running, but no real task is being completed.

  5. A worker dies or stalls and nobody knows until a client complains.

  6. Keys end up in prompts, logs, screenshots, repos, or shell history.

  7. Agents can spend, deploy, delete, or message customers without a human checkpoint.

  8. Sessions expire, tabs drift, and browser tasks fail without a trace.

  9. Retries or parallel workers process the same task twice and create conflicting output.

  10. Backups are missing, stale, or impossible to restore during an incident.

  11. One model is used for everything instead of routing by risk, cost, and difficulty.

  12. No runbook, no smoke test, and no evidence that the owner can operate it.
