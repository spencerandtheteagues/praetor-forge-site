Use rules, integrations and AI for the steps they fit

Business process automation does not need a model at every step. Explicit code handles known transformations and math, API integration services carry structured records reliably between systems, and custom internal tools surface exceptions and manual review queues cleanly.

Build an explicit path from intake to approval

  1. Intake: identify the request and preserve its primary-source documents.
  2. Preparation: normalize records and gather the context downstream steps require.
  3. Interpretation: invoke a model where unstructured document reading or classification adds value.
  4. Validation: cross-check required fields, deterministic calculations and source citations.
  5. Review: present a person with the evidence and proposed action before any consequential external step runs.

Workflow automation questions

When should a business workflow use deterministic rules instead of an AI model?

Deterministic calculations, field mappings, and permission checks belong in explicit code. AI models are reserved for unstructured reading, extraction, or classification, and every model output is validated before another system acts on it.

How do human approval gates work in an automated workflow?

Routine intake, normalization, and validation run automatically, while any step that sends customer correspondence, modifies external records, or commits spend pauses with its source evidence until an authorized reviewer approves it.

Who owns the workflow automation code and credentials after delivery?

Once the final invoice is paid, your company owns the private Git repository, setup scripts, automated smoke tests, and runbook built for you, with a permanent licence to any reusable Harness Lab components inside them. API keys and credentials remain in your accounts and environment variables.
