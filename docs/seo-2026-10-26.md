The company site now publishes the full homepage as HTML and hydrates the same React application for interaction. Three static service pages add crawlable navigation and distinct service information. No dependencies or lockfile changes were required.

The service pages use self-referencing canonical URLs and are listed in the sitemap. Links to the engineering notes and TitleDesk describe their actual relationship; the domains remain separate destinations with distinct content.

## Build and privacy checks

`npm run build` runs the client build and a local React pre-render. The pre-render gate requires complete homepage content and a contact form with POST semantics and a disabled fieldset. Controls become enabled only after the client mounts. A static email alternative remains available when JavaScript fails or is disabled. The copyright year is stable between build and hydration.

`npm run lint` passes. A separate cross-site audit checks sitemap targets, titles, descriptions, one H1, canonical URLs, JSON-LD parsing, internal files and fragment targets. Negative controls establish that missing canonical tags, noindex sitemap pages, missing H1s and unsafe default form controls are detected.

Publish the built `dist` tree to the existing `gh-pages` deployment branch, preserving `CNAME` and `.nojekyll`. Source changes belong on `main`. Do not run an unreviewed dependency installation merely to publish an already-validated build.

## Measuring the outcome

Use Search Console query and page reports to compare impressions, clicks, CTR and position for the phrases above over subsequent weeks. Check that important canonical URLs are indexed. Download-plan query variants should remain canonicalized to the download page.

Technical improvements do not establish a first-page ranking. Google explains that changes can take hours to months and that no technique automatically ranks a site first: https://developers.google.com/search/docs/fundamentals/seo-starter-guide
